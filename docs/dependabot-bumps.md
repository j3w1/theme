# Reviewing Dependabot npm bumps

For a Dependabot PR that changes `package.json`, a workspace `package.json`, or `package-lock.json`, the read-only `dependabot-refresh` job checks out the **PR head SHA**, installs locked dependencies, runs `npm run generate` and `npm run check`, and offers a patch if committed generated files changed. It never commits to the branch. A patch is a proposed change, not execution evidence or a passing check: the selected checks and `release-gate` still decide whether the bump is compatible.

1. Read the job summary. **No generated drift** means there is nothing to apply; the required checks must still pass. A failed install, generation or generated-file check, or an unexpected modification, needs investigation and produces no patch. An API or behavior failure in the selected checks needs a compatibility fix; never apply a patch to hide it.
2. When the summary names `dependabot-generated-patch`, download that artifact from the PR's workflow run (or `gh run download <run-id> -n dependabot-generated-patch -D .cache/dependabot-download`) and, if you downloaded it from the browser, extract `dependabot-refresh.patch`. The artifact expires after seven days.
3. Check out the PR branch (`gh pr checkout <pr-number>`). `git status --short` must be empty and `git rev-parse HEAD` must equal the **exact PR head SHA in the job summary**; if they differ, use a newer run's patch.
4. From the repository root, run `git apply --check .cache/dependabot-download/dependabot-refresh.patch`, then `git apply .cache/dependabot-download/dependabot-refresh.patch` (use your actual download path). Review `git diff --check`, `git diff --stat` and the whole `git diff`. Never apply blindly or commit unrelated files.
5. With Node 24, run `npm ci`, `npm run check` (the applied patch should already be current), `npm run generate`, then `npm run validate`, `npm run check` and the checks selected by `node scripts/ci/select.mjs --event pull_request --base origin/main --head HEAD`; for a dependency bump that is normally the full unit, build, browser and consumer gates (`npm run test:all` locally, after browser dependencies are installed). Commit only the reviewed generated changes and any separately justified compatibility fix to the PR branch if you may push; otherwise arrange a reviewable follow-up change. Never give PR code a write token.

GitHub Actions-only bumps generate no patch; ordinary CI still evaluates them. An artifact, a successful informational job or a subset of checks is never a green `release-gate`.
