# Reviewing Dependabot npm bumps

For a Dependabot PR that changes `package.json`, a workspace `package.json`, or `package-lock.json`, the read-only `dependabot-refresh` job checks out the **PR head SHA**, installs locked dependencies, runs `npm run generate` and `npm run check`, and offers a patch if committed generated files changed. It does not commit to the branch. The normal selected checks and `release-gate` still decide whether the bump is compatible. A patch is a proposed change, not execution evidence or a passing check.

1. Read the job summary. **No generated drift** means there is no artifact to apply; the required checks must still pass. A failed install, generation, generated-file check, or unexpected modification needs investigation and produces no patch. An API or behavior failure in selected checks needs a compatibility fix; never apply a patch to hide that failure.
2. When the summary names `dependabot-generated-patch`, download that artifact from the PR's workflow run (or run `gh run download <run-id> -n dependabot-generated-patch -D .cache/dependabot-download`). Extract it if downloading from the browser; the file is `dependabot-refresh.patch`. The artifact expires after seven days.
3. Check out the PR branch (`gh pr checkout <pr-number>`). Require `git status --short` to be empty and compare `git rev-parse HEAD` with the **exact PR head SHA in the job summary**. If they differ, use a newer run's patch; do not apply an old patch to a moved head.
4. From the repository root, run `git apply --check .cache/dependabot-download/dependabot-refresh.patch` and then `git apply .cache/dependabot-download/dependabot-refresh.patch` (use the actual path where you downloaded it). Review `git diff --check`, `git diff --stat` and `git diff` including additions and removals. Never apply blindly or commit unrelated files.
5. With Node 24, run `npm ci`, `npm run check` (the applied patch should already be current), `npm run generate`, then `npm run validate`, `npm run check` and the checks selected by `node scripts/ci/select.mjs --event pull_request --base origin/main --head HEAD`. For a dependency bump this normally means the full unit, build, browser and consumer gates; `npm run test:all` is the local full-suite command after browser dependencies are installed. Commit only the reviewed generated changes and any separately justified compatibility fix to the PR branch if you have permission to push. Otherwise arrange a reviewable follow-up change; do not give PR code a write token.

GitHub Actions-only bumps do not generate a patch; ordinary CI still evaluates them. If regeneration or the compatibility suite fails, do not treat an artifact, a successful informational job, or a subset of checks as a green `release-gate`.
